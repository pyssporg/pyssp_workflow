# ADR-005: One `bind` Call Instead of a Binding Record Union

**Status:** Accepted
**Layer:** architecture-decision

---

## Context

ADR-004 gave `binding` a closed union of five records — `ExternalStudy`,
`InlineRoot`, `TargetNamedExternal`, `InlineComponents`, `InlineWithMapping` —
and `apply_bindings`, which branched on the record type. Each record encoded one
combination of three independent choices: where the parameter set lives
(external or inline), how it is keyed (SSV member names or SSP target names),
and whether it is split per component. A new combination required a new record
and a new branch even though the operation and its standard-artifact inputs
were the same. Callers chose a record type instead of naming the artifact,
key space, and placement they wanted, and the type name carried a distinction
the arguments could state directly.

## Decision

Binding is one function:

```text
bind(build, ssv, *, set_name=None, mode="external"|"inline", ssm=None,
     mapping="attach"|"flatten", components=None) -> BindingResult
```

- `ssv` is the only value input, read once and read-only. `ssm` is the
  optional, read-only mapping artifact.
- The explicit axes are `mode` (external or inline placement), `mapping`
  (keep member names as `attach`, or resolve them to targets as `flatten`),
  and `components` (split inline flattened output per component).
- `BindingResult` is the output: the SSP, mode, mapping, parameter set,
  resource names, written component paths, and parameter count.
- Delete the five records, the `Binding` union, and `apply_bindings`;
  `__all__` is `["BindingResult", "bind"]`, and `binding` no longer imports
  `study`.

This supersedes the binding-union part of ADR-004. ADR-004's module layout,
`BuiltFixture` ownership, and layering rules stand.

## Rationale

Call sites now name the artifact (`ssv`, optional `ssm`), the key space
(`set_name` and `mapping`), and the placement (`mode`, `components`) directly.
The closed union forced a type per combination, so adding a variant changed the
public surface rather than extending an argument contract, and the type name
substituted for the three decisions it concealed. One function with explicit
keyword axes keeps the surface small while the four placements remain separate
internal helpers.

## Consequences

- A new placement extends the `mode`/`mapping` contract or the `components`
  rule instead of adding a public record.
- Invalid combinations fail at call time: `components` with external mode,
  `components` with `attach` mapping, and inline `attach` without `ssm` raise
  `ValueError`.
- `BindingResult` is plain data, so callers can tell which resources and
  component sets were written without re-reading the SSP.
- `binding` imports only `pyssp_standard` and `fixture`; `study` is no longer
  a dependency.
- Only `build.model_dir` is mutated; the input SSV and SSM stay read-only.
- Value reading and mapping resolution are delegated to `pyssp_standard`
  (`SSV.parameters_by_name`, `SSM.resolve`), so parameters keep their SSV type
  instead of being coerced to `float`.

## Alternatives considered

1. **Keep the union and add a record for each new combination.** Rejected: the
   number of records tracks the number of combinations, and each one repeats
   the same inputs and branch shape.
2. **Expose one function per placement.** Rejected: the placements share the
   same inputs and differ only in arguments, so four names would move the
   combination back into the call site's choice of function.
3. **Accept a configuration record with the axes as fields.** Rejected: it adds
   a type with no behaviour, while keyword arguments already name the axes.
