# ADR-004: Module Surfaces Follow Responsibilities

**Status:** Accepted
**Layer:** architecture-decision

---

## Context

The first module layout mirrored the stages of a flow: `authoring`, `params`,
`packaging`, `execute`, `plan`, `report`, `cli`. Several of those modules were
named empty contracts, and their names described a mechanism or a stage rather
than the data the module owns.

Two concrete problems followed. `packaging` imported `authoring.FixtureBuild`,
so the module that applies a scenario depended on the build module for a record
that is not itself a build step; `authoring` and `binding` needed the same record
but neither owned it. `params` re-read the study scenario that the study
descriptor already named, and `execute` was a thin wrapper around measurement.
`plan`, `report`, and `cli` were empty stubs, and `ComparisonRecord` carried
`status`/`error` fields that no producer filled.

## Decision

Replace the stage-shaped layout with one module per responsibility.

- `params` becomes `study`: `Experiment`, `StudyDescriptor`,
  `read_study_descriptor`, `Scenario`, `read_scenario`, and `scenario_targets`.
  It reads the descriptor and the standard SSV/SSM as plain data.
- `packaging` becomes `binding`: the `Binding` union (`ExternalStudy`,
  `InlineRoot`, `TargetNamedExternal`, `InlineComponents`, `InlineWithMapping`)
  and `apply_bindings`, which writes the chosen binding into a built SSP.
- `execute` becomes `compare`: `ResultRef`, `ComparisonRequest`,
  `ComparisonRecord`, and `compare_csvs`.
- `authoring.FixtureBuild` becomes `fixture.BuiltFixture`. The `fixture` module
  also owns `artifacts_root`, `study_dir`, and `model_dir`.
- Delete the empty `plan`, `report`, and `cli` stubs.
- Remove `ComparisonRecord.status` and `ComparisonRecord.error`; a comparison
  record reports what was measured, not whether it is acceptable.
- Consolidate duplicated helpers: `_process.find_executable` and
  `_process.run`, `_dirs.reset_dir`, `_fmu.strip_model_exchange` and
  `_fmu.strip_fmu`, the fixture path helpers, and one
  `DEFAULT_TIMEOUT_SECONDS` used by the authoring nodes.

## Rationale

A module name should say what the module is, not which flow stage happened to
call it. `study`, `binding`, `compare`, and `fixture` name the records and
operations they own, which makes the import graph acyclic: `fixture` imports
only `study`; `authoring` and `binding` both import `fixture` and `study`, so
neither depends on the other. Deleting empty stubs removes surfaces that promised
behaviour without implementing it, and removing the dead comparison fields stops
callers from inventing a status the layer never produced.

## Consequences

- `authoring` still never imports `pyssp_vv`; only `nodes` may import
  `pyssp_vv.judge`.
- The `Binding` union is closed: a new binding shape is a new record and a new
  branch in `apply_bindings`.
- `ComparisonRecord` stays plain data and round-trips through `to_dict` and
  `from_dict` without a verdict field; thresholds, manifests, and artifact
  layout remain the caller's responsibility.
- `BuiltFixture` is shared by `authoring` and `binding` without either module
  owning the other.
- The layering rules in `architecture.md` are the contract;
  `tests/test_layering.py` enforces them.

## Alternatives considered

1. **Keep the stage names and only delete the empty stubs.** Rejected: the
   `packaging` -> `authoring.FixtureBuild` dependency still points the wrong way,
   and `params` still duplicates scenario reading.
2. **Keep `FixtureBuild` in `authoring`.** Rejected: `binding` needs the record
   without needing a build, so the record belongs to a module both can import.
3. **Keep `status`/`error` on `ComparisonRecord` for forward compatibility.**
   Rejected: no producer set them, and their presence implied that this layer
   produces a verdict.
