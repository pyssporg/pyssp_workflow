# ADR-001: Node-First Composition

**Status:** Accepted
**Layer:** architecture-decision

---

## Context

The workflow layer must run build, simulate, measure, and judge steps in
parallel and with an audit trail. The available orchestration engine is
`sequence_extensions`, whose unit of work is the `@node` function.

Two shapes were possible: make every workflow function a node, or keep plain
functions and wrap only the units that need scheduling policy.

## Decision

Adopt the second option.

- Plain functions in the workflow modules do the work.
- `pyssp_workflow.nodes` applies `@node` to work units at artifact boundaries.
- Node inputs and outputs are paths and plain data, so they survive a process
  pool.
- The capability itself lives in `pyssp_vv`; this package wraps it.

## Rationale

`@node` is a policy annotation, not a behavioural wrapper: called directly it
runs inline. The real constraints it imposes are picklability, cancellation, and
abort containment. Keeping nodes in one layer makes the flow engine an optional
extra and prevents its types from reaching consumers who do not want it.

## Consequences

- Domain signatures never mention `sequence_extensions`.
- A node's contract is catalogued because flows are user code.
- Retries and timeouts are declared per node, where they are visible.
- Engine nodes run in a child process.
- Node granularity is the artifact boundary: coarser prevents parallelism and
  hides which artifact a step produces; finer produces trivial nodes.
