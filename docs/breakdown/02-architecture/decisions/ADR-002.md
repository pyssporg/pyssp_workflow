# ADR-002: Explicit Path Addressing

**Status:** Accepted
**Layer:** architecture-decision

---

## Context

Consumers hold SSP models in their own layouts, and some flows consume artifacts
produced elsewhere. Nodes must stay picklable for process pools.

## Decision

- Every public function and node takes explicit paths for inputs and an explicit
  output directory.
- Outputs are derived from the assessment identifier *within* the output
  directory, never from the process working directory.
- A convenience helper may compute conventional paths, but it returns plain
  paths and plain data, holds no open handles, and is never required.
- Functions return absolute paths; manifests relativise them on write.

## Rationale

Project-root conventions make every function working-directory sensitive and
unusable for a consumer with a different layout. An injected resolver creates
two code paths and two failure modes per call and weakens picklability.
Explicit paths make the artifact dependency graph visible at the call site.

## Consequences

- Signatures are longer; paths are grouped into small frozen dataclasses rather
  than long positional lists.
- A node's output location is predictable from its arguments, which makes "one
  node owns one output path" checkable.
- Callers choose directories; nodes create them.
